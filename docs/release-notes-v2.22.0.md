# v2.22.0 Release Notes（2026-09-01）

**门禁双向修正：防绕过 + 防干扰 + 省 token**

本版本针对三个真实使用反馈一次性修正：门禁能被 Agent 骗过、门禁干扰正常任务运行、注入链路费 token。

---

## 一、防绕过：门禁不再能被骗

**旧版漏洞**：门禁的判定依据是几个状态文件，而这些文件对 Agent 可写——写一个 `.constitution-simple` 豁免旗标文件即可让全部任务跳过门禁；直接改 `.constitution-state.json` 即可伪造"三查已通过"。

**v2.22.0 修正**：
- 门禁自身四个文件（三查记录 / 豁免旗标 / 违规记录 / 注入上下文）一律禁止 Agent 经 Write/Edit/Bash（重定向、tee、heredoc、rm、mv、cp、sed -i）篡改，违者当次工具调用直接被拦；只读不拦
- Bash 写文件检测补上 `sed -i`（就地改写也是写文件）
- step1 只认 `level=PASS` 的真实校验结果，降级/手写状态条目不再产生通行证

## 二、防干扰：门禁不再误伤已合规任务

**旧版问题**：任务开始时 Agent 已经查了记忆、查了技能、调用了技能，任务中途门禁仍然拦截；收尾阶段还会因为"最终回复没复述三查"误记违规，下个任务开头被误注入警告。

**v2.22.0 引入「三查证据链」**，满足其一即放行写操作、收尾不重复校验：

1. **手动路径**：本任务内 `constitution-check --step 1` 真实校验通过（原有行为）
2. **注入路径（新增）**：平台已注入记忆+技能树（注入上下文 ready）+ 本任务内实际调用过技能。Skill 工具调用由门禁在 PreToolUse 自动记录，Agent 无需手动跑任何校验命令

配套修正：
- **追加式消息不重置**：「继续 / 好的 / 下一步 / ok / continue」这类延续消息不再重置门禁状态，同一任务的证据持续有效
- **Stop 防误记**：已有证据链的任务收尾时跳过重复文本校验，不再误记违规
- **注入自愈**：`user-prompt-submit.sh` 发现注入上下文缺失/过期时现场重跑 SessionStart 注入（幂等），而不是直接【宪法拦截】挡住任务

## 三、省 token：回到"尽量省"的初衷

| 项目 | 旧 | 新 |
|------|-----|-----|
| SAD 候选注入 | 6 条 | 4 条 |
| 候选描述截断 | 60 字 | 40 字 |
| 每分类技能清单 | 12 个 | 8 个 |
| 记忆片段上限 | 1200 字 | 900 字 |
| hooks.json matcher | 约 8KB 关键词列表 | `.*`（分类在 hook 内做） |
| SKILL.md 版本史 | 6 段摘要置顶 | 1 行 + 指向 CHANGELOG |
| 阻断提示文案 | 4 行长命令 | 2 行补救路径 |

单次注入块约省 30% token；SKILL.md 每次加载省约 1K token。

## 升级方式

```bash
git pull                      # 或重新 clone
bash install.sh               # 技能目录型平台：覆盖安装 + 自动重建技能树
python scripts/register_hooks.py   # 已注册过钩子的无需重跑（钩子指向脚本，脚本已更新）
python scripts/tests/run_tests.py  # 应显示 77/77 通过
```

## 兼容性说明

- 证据链机制对旧行为**只放宽不收紧**：原来靠手动 `constitution-check` 的流程完全不变；"注入+调用技能"是新增的放行路径
- 追加式消息判定偏宽松方向（宁可少拦不误拦），超短新任务（≤8 字符）会被视为延续——这是防干扰的有意取舍
- 门禁文件保护不影响人工运维：你自己在终端改这些文件不受任何影响（保护只作用于 Agent 的工具调用）
